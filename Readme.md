# 商用级小说改剧本多智能体体系：角色定义 + 全流程节点清单
**文档版本**：v1.1
**适用范围**：40-100万字长篇小说影视剧/短剧/漫剧改编
**核心设计原则**：中心化调度、单一数据源、创作/资产/校验三权分立

---

## 一、整体架构核心原则
1.  **星型中心化调度**：所有执行Agent仅与「项目调度Agent」通信，不发生点对点自由对话，避免传话失真与逻辑漂移。
2.  **单一数据源**：所有核心数据存入「共享工作区」，分**只读资产层**（官方设定，仅资产类Agent可修改）和**可写工作层**（过程产出），所有Agent执行前强制拉取最新数据，禁止本地缓存。
3.  **节点化准入准出**：每个工作节点有明确的准入条件和准出校验标准，校验不通过绝不进入下一环节，误差锁死在当前节点。
4.  **权责分离**：资产管理、内容创作、合规校验三类角色完全独立，禁止既做创作又做校验。

---

## 二、全角色定义清单
共5大类13个角色，每个角色职责单一、边界清晰，可独立封装为模型服务。

### （一）调度编排层 · 1个
#### 项目调度Agent
- **核心定位**：全流程大脑，相当于项目制片人+流程经理，唯一掌握全局进度的节点。
- **核心职责**：
  1.  项目初始化，创建共享工作区目录结构；
  2.  按流程节点拆分任务，定向分发给对应执行Agent；
  3.  接收任务回执，校验产出完整性，触发下一节点或回退修改；
  4.  异常处理：超时、校验失败超限、内容冲突时的升级与回滚；
  5.  管理并行任务（如多集剧本同时生成）的资源调度。
- **输入**：项目配置信息（原著文件、改编体量、题材类型）、各Agent任务回执
- **输出**：结构化任务指令、进度状态、异常处理指令
- **权限**：全工作区读写权限，可触发节点回滚与版本回溯

### （二）资产管理层 · 4个
> 唯一有权修改「只读资产层」的角色，产出是全项目的官方基准，所有创作内容必须与之对齐。

#### 1. 原著解构Agent
- **核心定位**：长文本拆解专家，全项目的信息入口，拆分质量直接决定后续摘要、资产库的信息完整度与全局一致性。
- **核心职责**：
  1.  自动识别原著章节、卷篇的天然叙事边界，遵循「语义优先、字数为辅」的三级拆分原则，将全文拆分为独立语义块；优先保证叙事单元完整性，绝对禁止按纯字数硬切情节。
  2.  自下而上生成分层摘要：章节摘要→剧情单元摘要→全局故事摘要，每层摘要均按固定维度结构化提取信息，而非泛化文本压缩。
  3.  首轮全量信息提取：逐块标记出场人物、关键事件、场景地点、伏笔埋设、世界观细节五类基础标签。
  4.  为每个语义块附加标准化元信息标签，支撑后续聚合、检索与交叉校验。
- **输入**：原著全文文件
- **输出**：带元信息的语义块集合、分层摘要体系、原著基础信息标签库
- **权限**：仅可写入「可写工作层-原著解构目录」，不可直接修改正式资产库

#### 2. 人设资产管理Agent
- **核心定位**：人物设定唯一官方管理员，全项目人设的最终解释方。
- **核心职责**：
  1.  跨章节聚合人物信息，生成标准人物档案（身份、外貌、性格、语言风格、人物弧光、关键经历、人际关系网）；
  2.  维护人物状态时间线：标注每个关键节点后人物的性格、身份、关系变化；
  3.  处理人设冲突，输出官方统一设定；
  4.  响应校验Agent的人设查询，提供基准数据。
- **输入**：原著解构标签、全剧人物弧光规划
- **输出**：正式人物资产库（只读）、人物状态时间轴
- **权限**：唯一可写入「只读资产层-人物库」的角色

#### 3. 世界观资产管理Agent
- **核心定位**：世界设定与美学规则管理员。
- **核心职责**：
  1.  提取并整合时代背景、地理设定、势力划分、社会规则、服饰器物、礼仪称谓等设定；
  2.  架空题材锚定真实历史参照，统一全剧美学基准；
  3.  生成场景资产库：核心场景的空间布局、视觉基调、出场功能。
- **输入**：原著解构标签、改编策划案
- **输出**：正式世界观资产库（只读）、核心场景资产库
- **权限**：唯一可写入「只读资产层-世界观库」的角色

#### 4. 时间线管理Agent
- **核心定位**：全剧叙事时间的唯一基准管理员。
- **核心职责**：
  1.  梳理主线、支线的绝对时间轴，标注关键事件的时间节点；
  2.  处理多线叙事的时间对应关系，排查时间悖论；
  3.  维护伏笔-回收对应表，标记所有伏笔的埋设位置与回收节点。
- **输入**：原著解构标签、分集大纲
- **输出**：正式全局时间轴（只读）、伏笔回收对照表
- **权限**：唯一可写入「只读资产层-时间线库」的角色

### （三）创作执行层 · 4个
> 仅负责对应环节的内容创作，无权限修改官方资产，输出必须经过校验才能入库。

#### 1. 改编策划Agent
- **核心定位**：改编总设计师，确定改编方向与取舍原则。
- **核心职责**：
  1.  基于原著全局摘要，确定改编核心定位、目标受众、核心卖点；
  2.  制定内容取舍原则：明确保留主线、删减支线、合并角色的清单与理由；
  3.  提炼全剧主题内核，确定整体叙事风格与台词风格。
- **输入**：原著全局摘要、项目配置要求
- **输出**：《改编策划总纲》
- **权限**：仅可写入「可写工作层-策划目录」，需通过后才能作为后续基准

#### 2. 分集大纲Agent
- **核心定位**：全局结构设计师，搭建全剧骨架。
- **核心职责**：
  1.  按三幕式结构拆分全剧的幕、集节点，确定每集核心冲突与结尾钩子；
  2.  分配主线、支线在各集的占比与推进节奏；
  3.  标注每集的关键转折点、人物成长节点、伏笔埋设点。
- **输入**：《改编策划总纲》、全局故事摘要、官方资产库
- **输出**：《全剧分集大纲》
- **权限**：仅可写入「可写工作层-大纲目录」

#### 3. 场次拆分Agent
- **核心定位**：单集内容拆解师，把分集大纲落地为可执行的场次颗粒。
- **核心职责**：
  1.  将单集大纲拆分为15-25场戏，明确每场的叙事功能（推进剧情/塑造人物/铺垫伏笔/制造冲突）；
  2.  标注每场的出场人物、场景、时间、对应原著片段；
  3.  设计每场的起承转合与核心信息增量，删除无效水戏。
- **输入**：单集大纲、对应原著章节摘要、官方资产库
- **输出**：《单集场次清单》
- **权限**：仅可写入「可写工作层-场次目录」

#### 4. 单场剧本Agent
- **核心定位**：内容生产执行单元，批量生成单场剧本初稿。
- **核心职责**：
  1.  基于场次指令，拉取对应原文片段、人物设定、场景设定；
  2.  按标准剧本格式完成小说到视听语言的转化；
  3.  严格遵守改编规则（无心理独白、台词符合人设、细节符合世界观）。
- **输入**：单场任务指令、对应原文片段、相关人设/场景设定
- **输出**：单场剧本初稿
- **权限**：仅可写入「可写工作层-剧本初稿目录」，校验通过后转入正式库

### （四）校验审计层 · 3个
> 独立第三方角色，不参与创作，仅基于官方资产库做合规性校验，输出结构化问题清单。

#### 1. 人设一致性校验Agent
- **核心职责**：对比剧本内容与官方人物资产库，排查人设偏差。
- **校验维度**：行为逻辑、语言风格、称谓习惯、人物关系、状态时间线匹配度
- **输出**：人设校验报告（合规/不合规+具体问题点+修正建议）

#### 2. 时间线与伏笔校验Agent
- **核心职责**：校验剧情时间逻辑与伏笔回收完整性。
- **校验维度**：时间线是否冲突、事件顺序是否正确、伏笔是否按计划埋设/回收、场景时间是否连贯
- **输出**：时间线校验报告（合规/不合规+具体问题点+修正建议）

#### 3. 格式与合规校验Agent
- **核心职责**：校验格式规范与基础合规性。
- **校验维度**：剧本格式标准度、台词是否有穿越词汇、世界观细节是否符合设定、是否有违禁内容
- **输出**：格式合规校验报告

### （五）统稿优化层 · 1个
#### 全局统稿Agent
- **核心定位**：最终质量打磨师，负责全稿风格统一与节奏优化。
- **核心职责**：
  1.  统一全剧台词风格、叙事节奏，修正不同场次的文风差异；
  2.  优化整体叙事流畅度，补全场次间的过渡衔接；
  3.  基于全局视角，调整关键情节的情绪张力与节奏快慢。
- **输入**：全剧正式剧本初稿、官方资产库
- **输出**：全剧剧本终稿
- **权限**：可修改正式剧本库内容，保留修改痕迹

## 四、核心节点专项细则
### 4.1 N02 节点：语义块拆分专项规则
本细则为节点核心执行逻辑的落地补充，原著解构Agent必须严格遵循，从根源控制拆分质量对后续全流程的传导影响。

#### 4.1.1 三级拆分优先级（从高到低，禁止跨级硬切）
拆分严格按「天然叙事边界 > 剧情语义边界 > 字数兜底约束」的顺序判断，绝不以纯字数为第一标准。
- **一级边界（最高优先级）**：原著章节、卷、篇的天然分隔线。绝不跨章节、跨剧情大单元强行合并或拆分，优先保留单章叙事完整性。
- **二级边界（次优先级）**：章节内的剧情语义转场点。仅当单章体量超标时启用，仅在场景切换、时间跳转、核心人物更换、主情节段落收尾、对话结束处拆分，禁止在动作戏、关键对话、高潮情节中段切割。
- **三级边界（兜底约束）**：字数弹性区间。仅作为合规性校验的兜底标准，根据项目选用的基础模型能力动态调整。

#### 4.1.2 字数偏离的影响与风险控制
字数区间的本质是平衡「信息完整度」与「模型处理质量」，偏离区间会直接影响后续全链路产出，对应风险与控制规则如下：
- **单块过小（低于对应模型下限）**
  核心影响：语义块数量激增，分层摘要聚合次数增多，信息误差逐层累积，易导致全局摘要丢失细节逻辑；人物、伏笔等标签碎片化；模型调用成本与耗时翻倍。
  控制规则：单章字数不足1500字时，仅可与同剧情单元的相邻章节合并，直至触低下限或该剧情单元结束；禁止跨卷、跨核心剧情单元合并。
- **单块过大（高于对应模型上限）**
  核心影响：模型输入占比过高，输出空间被挤压，摘要被迫粗化，遗漏次要人物、关键伏笔、世界观细节；触发长文本「中段遗忘」效应，块内中间部分信息提取质量显著下降。
  控制规则：单章字数超上限时，必须在章节内按二级语义边界拆分为多个子块，每个子块严格控制在弹性区间内，拆分后保留所属章节与剧情单元的关联元信息。

#### 4.1.3 分模型适配的弹性字数区间
根据项目选用的基础模型上下文窗口，动态匹配拆分字数标准；中文按1字≈1.3-1.5token换算，统一预留50%上下文空间用于输出摘要与标签。
| 模型上下文能力 | 单块字数弹性区间 | 单章免拆分阈值 | 适用场景 |
| :--- | :--- | :--- | :--- |
| 8K 通用模型 | 2000-5000字 | 5000字以内整章处理 | 中小体量项目、低成本快速落地 |
| 16K-32K 主流模型 | 3000-8000字 | 8000字以内整章处理 | 主流商用项目、平衡质量与成本 |
| 128K+ 长上下文模型 | 5000-20000字 | 20000字以内整章处理 | 高质量精品项目、最大化保留叙事完整性 |

#### 4.1.4 语义块强制元信息
每个拆分完成的语义块，必须附带以下结构化元信息，用于后续聚合、检索与校验：
- 所属卷/部、所属章节、所属剧情单元
- 核心出场人物、核心场景、核心事件类型
- 语义块序号、前后块关联标识

### 4.2 N03 节点：首轮资产库构建配置细则

#### 4.2.3 子节点1：人物资产库构建
- **执行角色**：人设资产管理Agent
- **输入数据**：章节级人物标签、全局摘要人物信息、原著基础出场人物清单
- **执行步骤**：
  1.  **全量聚合**：按人物姓名/别名，跨章节聚合所有相关信息，合并重复条目，统一人物唯一标识；
  2.  **字段补全**：按标准字段填充人物信息，信息不足的标注「待补充」，禁止编造；
  3.  **去重合并**：识别同一人物的不同称谓（本名、字号、外号、身份代称），合并为同一档案，标注所有别名；
  4.  **关系梳理**：梳理人物间的核心关系（亲属、敌对、盟友、师徒等），生成初步人物关系网；
  5.  **初校验**：排查同一人物的年龄、身份、性格是否存在前后明显矛盾，存在矛盾的标注「冲突待确认」，并列出冲突点原文依据。
- **输出字段规范**：
  | 字段名 | 说明 | 必填性 |
  | :--- | :--- | :--- |
  | 人物ID | 唯一标识，如CHAR-001 | 必填 |
  | 姓名/别名 | 本名、字号、外号、所有剧中称谓 | 必填 |
  | 核心身份 | 开篇身份、核心社会定位 | 必填 |
  | 外貌特征 | 标志性外貌、服饰特征 | 选填 |
  | 核心性格 | 开篇核心性格特质、行为模式 | 必填 |
  | 语言风格 | 台词特点、说话习惯 | 选填 |
  | 关键经历 | 原著中影响人物的核心过往事件 | 必填 |
  | 人物目标 | 原著中的核心诉求与终极目标 | 必填 |
  | 人物关系 | 与其他核心人物的关系及变化 | 必填 |
  | 人物弧光 | 从开篇到结局的性格/身份变化 | 选填 |
  | 标志性行为 | 贯穿全程的习惯性动作/偏好 | 选填 |
  | 冲突标记 | 原著中存在的设定矛盾点 | 有则填 |
- **准出标准**：核心人物（TOP10）字段完整度≥90%，次要人物字段完整度≥60%，明显冲突点全部标注。

#### 4.2.4 子节点2：世界观资产库构建
- **执行角色**：世界观资产管理Agent
- **输入数据**：章节级场景/设定标签、全局世界观摘要、原著时代/地理相关信息
- **执行步骤**：
  1.  **分类聚合**：按「时代背景、地理设定、势力划分、社会规则、服饰器物、礼仪称谓、核心场景」七大维度聚合信息；
  2.  **规则提炼**：提炼世界观的底层运行规则（如阶级制度、权力体系、特殊能力规则等），明确通用约束；
  3.  **场景建档**：对核心场景（出现≥3次或有关键情节）单独建档，标注空间特征、视觉氛围、出场功能；
  4.  **统一规范**：对称谓、官职、器物名称做统一，避免同一事物多种表述；
  5.  **初校验**：排查设定前后矛盾，如时间线与时代特征不符、规则前后不一致，标注冲突点。
- **输出字段规范**：
  1.  基础设定模块：时代背景、地理疆域、核心势力、社会阶层、通用规则
  2.  文化细节模块：服饰规制、饮食器物、礼仪称谓、习俗制度
  3.  核心场景库：场景ID、场景名称、空间类型、视觉特征、出现章节、核心功能
- **准出标准**：七大维度无核心缺失，核心场景全部建档，基础规则无明显逻辑冲突。

#### 4.2.5 子节点3：全局时间线构建
- **执行角色**：时间线管理Agent
- **输入数据**：章节级事件标签、全局故事摘要、关键节点时间信息
- **执行步骤**：
  1.  **事件提取**：提取所有影响主线的关键事件，标注事件发生的相对/绝对时间、涉及人物、发生地点；
  2.  **时序排序**：按时间先后排序，梳理主线时间轴，标注支线事件的时间对应关系；
  3.  **伏笔标记**：识别所有伏笔埋设事件与对应回收事件，生成初步伏笔-回收对照表；
  4.  **初校验**：排查时间悖论（如人物年龄与事件时间不符、因果倒置），标注冲突点。
- **输出字段规范**：
  1.  主线时间轴：时间节点、核心事件、涉及人物、事件影响
  2.  支线时间轴：各支线的关键事件与主线时间对应关系
  3.  伏笔回收对照表：伏笔ID、埋设位置（章节）、伏笔内容、回收位置（章节）、回收方式
- **准出标准**：主线关键事件无遗漏，时序逻辑正确，明显伏笔全部标记，无核心时间悖论。

#### 4.2.6 跨资产一致性校验（节点必经环节）
- **触发条件**：三个子节点全部完成初稿
- **执行逻辑**：由项目调度Agent触发，三个Agent交叉校验对方数据
  1.  人物经历 vs 时间线：校验人物关键经历是否与时间轴节点对应；
  2.  人物身份 vs 世界观：校验人物身份、称谓是否符合世界观的社会规则；
  3.  场景事件 vs 时间线：校验核心场景的关键事件是否与时序匹配。
- **异常处理**：发现不一致处，标注问题点，退回对应Agent修正；单轮修正上限2次，超限则标记为「待人工确认」，不阻塞流程，留待后续节点人工处理。
- **最终发布**：校验通过后，正式发布「官方资产库v1.0」，存入共享工作区工作层，供N04改编策划调用。

## 六、商用级配套落地机制
1.  **版本管理机制**：所有资产与剧本均带版本号，修改自动生成新版本，保留历史回溯能力；官方资产库升级需走审批流程。
2.  **回滚机制**：任意节点出现问题，可一键回滚到上一稳定版本，避免错误传导。
3.  **并行调度规则**：同阶段内的独立任务（如多集拆分、多场生成）可并行，有依赖关系的节点严格串行。
4.  **人工介入节点**：在N05（策划案）、N08（大纲）、N20（终稿）设置人工审核节点，关键决策由人把控，AI负责执行与校验。

## 七、落地技术栈参考
- **轻量快速落地版**：LangGraph（工作流编排）+ 通用大模型 + 本地向量库 + SQLite（存结构化资产），适合中小团队快速搭建原型。
- **企业级商用版**：自研工作流引擎 + 微调专用模型（各角色独立微调）+ 关系型数据库（资产库）+ 向量数据库（原文检索）+ 对象存储（文件管理），支持高并发批量生成。
