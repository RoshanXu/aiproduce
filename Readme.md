# 商用级小说改剧本多智能体体系：角色定义 + 全流程节点清单
**文档版本**：v1.1
**适用范围**：40-100万字长篇小说影视剧/短剧/漫剧改编
**核心设计原则**：中心化调度、单一数据源、创作/资产/校验三权分立

---

## 一、整体架构核心原则
1.  **星型中心化调度**：所有执行Agent仅与「项目调度Agent」通信，不发生点对点自由对话，避免传话失真与逻辑漂移。
2.  **单一数据源**：所有核心数据存入「共享工作区」，分**只读资产层**（官方设定，仅资产类Agent可修改）和**可写工作层**（过程产出），所有Agent执行前强制拉取最新数据，禁止本地缓存。
3.  **节点化准入准出**：每个工作节点有明确的准入条件和准出校验标准，校验不通过绝不进入下一环节，误差锁死在当前节点。
4.  **权责分离**：资产管理、内容创作、合规校验三类角色完全独立，禁止既做创作又做校验。

---

## 二、全角色定义清单
共5大类13个角色，每个角色职责单一、边界清晰，可独立封装为模型服务。

### （一）调度编排层 · 1个
#### 项目调度Agent
- **核心定位**：全流程大脑，相当于项目制片人+流程经理，唯一掌握全局进度的节点。
- **核心职责**：
  1.  项目初始化，创建共享工作区目录结构；
  2.  按流程节点拆分任务，定向分发给对应执行Agent；
  3.  接收任务回执，校验产出完整性，触发下一节点或回退修改；
  4.  异常处理：超时、校验失败超限、内容冲突时的升级与回滚；
  5.  管理并行任务（如多集剧本同时生成）的资源调度。
- **输入**：项目配置信息（原著文件、改编体量、题材类型）、各Agent任务回执
- **输出**：结构化任务指令、进度状态、异常处理指令
- **权限**：全工作区读写权限，可触发节点回滚与版本回溯

### （二）资产管理层 · 4个
> 唯一有权修改「只读资产层」的角色，产出是全项目的官方基准，所有创作内容必须与之对齐。

#### 1. 原著解构Agent
- **核心定位**：长文本拆解专家，全项目的信息入口，拆分质量直接决定后续摘要、资产库的信息完整度与全局一致性。
- **核心职责**：
  1.  自动识别原著章节、卷篇的天然叙事边界，遵循「语义优先、字数为辅」的三级拆分原则，将全文拆分为独立语义块；优先保证叙事单元完整性，绝对禁止按纯字数硬切情节。
  2.  自下而上生成分层摘要：章节摘要→剧情单元摘要→全局故事摘要，每层摘要均按固定维度结构化提取信息，而非泛化文本压缩。
  3.  首轮全量信息提取：逐块标记出场人物、关键事件、场景地点、伏笔埋设、世界观细节五类基础标签。
  4.  为每个语义块附加标准化元信息标签，支撑后续聚合、检索与交叉校验。
- **输入**：原著全文文件
- **输出**：带元信息的语义块集合、分层摘要体系、原著基础信息标签库
- **权限**：仅可写入「可写工作层-原著解构目录」，不可直接修改正式资产库

#### 2. 人设资产管理Agent
- **核心定位**：人物设定唯一官方管理员，全项目人设的最终解释方。
- **核心职责**：
  1.  跨章节聚合人物信息，生成标准人物档案（身份、外貌、性格、语言风格、人物弧光、关键经历、人际关系网）；
  2.  维护人物状态时间线：标注每个关键节点后人物的性格、身份、关系变化；
  3.  处理人设冲突，输出官方统一设定；
  4.  响应校验Agent的人设查询，提供基准数据。
- **输入**：原著解构标签、全剧人物弧光规划
- **输出**：正式人物资产库（只读）、人物状态时间轴
- **权限**：唯一可写入「只读资产层-人物库」的角色

#### 3. 世界观资产管理Agent
- **核心定位**：世界设定与美学规则管理员。
- **核心职责**：
  1.  提取并整合时代背景、地理设定、势力划分、社会规则、服饰器物、礼仪称谓等设定；
  2.  架空题材锚定真实历史参照，统一全剧美学基准；
  3.  生成场景资产库：核心场景的空间布局、视觉基调、出场功能。
- **输入**：原著解构标签、改编策划案
- **输出**：正式世界观资产库（只读）、核心场景资产库
- **权限**：唯一可写入「只读资产层-世界观库」的角色

#### 4. 时间线管理Agent
- **核心定位**：全剧叙事时间的唯一基准管理员。
- **核心职责**：
  1.  梳理主线、支线的绝对时间轴，标注关键事件的时间节点；
  2.  处理多线叙事的时间对应关系，排查时间悖论；
  3.  维护伏笔-回收对应表，标记所有伏笔的埋设位置与回收节点。
- **输入**：原著解构标签、分集大纲
- **输出**：正式全局时间轴（只读）、伏笔回收对照表
- **权限**：唯一可写入「只读资产层-时间线库」的角色

### （三）创作执行层 · 4个
> 仅负责对应环节的内容创作，无权限修改官方资产，输出必须经过校验才能入库。

#### 1. 改编策划Agent
- **核心定位**：改编总设计师，确定改编方向与取舍原则。
- **核心职责**：
  1.  基于原著全局摘要，确定改编核心定位、目标受众、核心卖点；
  2.  制定内容取舍原则：明确保留主线、删减支线、合并角色的清单与理由；
  3.  提炼全剧主题内核，确定整体叙事风格与台词风格。
- **输入**：原著全局摘要、项目配置要求
- **输出**：《改编策划总纲》
- **权限**：仅可写入「可写工作层-策划目录」，需通过后才能作为后续基准

#### 2. 分集大纲Agent
- **核心定位**：全局结构设计师，搭建全剧骨架。
- **核心职责**：
  1.  按三幕式结构拆分全剧的幕、集节点，确定每集核心冲突与结尾钩子；
  2.  分配主线、支线在各集的占比与推进节奏；
  3.  标注每集的关键转折点、人物成长节点、伏笔埋设点。
- **输入**：《改编策划总纲》、全局故事摘要、官方资产库
- **输出**：《全剧分集大纲》
- **权限**：仅可写入「可写工作层-大纲目录」

#### 3. 场次拆分Agent
- **核心定位**：单集内容拆解师，把分集大纲落地为可执行的场次颗粒。
- **核心职责**：
  1.  将单集大纲拆分为15-25场戏，明确每场的叙事功能（推进剧情/塑造人物/铺垫伏笔/制造冲突）；
  2.  标注每场的出场人物、场景、时间、对应原著片段；
  3.  设计每场的起承转合与核心信息增量，删除无效水戏。
- **输入**：单集大纲、对应原著章节摘要、官方资产库
- **输出**：《单集场次清单》
- **权限**：仅可写入「可写工作层-场次目录」

#### 4. 单场剧本Agent
- **核心定位**：内容生产执行单元，批量生成单场剧本初稿。
- **核心职责**：
  1.  基于场次指令，拉取对应原文片段、人物设定、场景设定；
  2.  按标准剧本格式完成小说到视听语言的转化；
  3.  严格遵守改编规则（无心理独白、台词符合人设、细节符合世界观）。
- **输入**：单场任务指令、对应原文片段、相关人设/场景设定
- **输出**：单场剧本初稿
- **权限**：仅可写入「可写工作层-剧本初稿目录」，校验通过后转入正式库

### （四）校验审计层 · 3个
> 独立第三方角色，不参与创作，仅基于官方资产库做合规性校验，输出结构化问题清单。

#### 1. 人设一致性校验Agent
- **核心职责**：对比剧本内容与官方人物资产库，排查人设偏差。
- **校验维度**：行为逻辑、语言风格、称谓习惯、人物关系、状态时间线匹配度
- **输出**：人设校验报告（合规/不合规+具体问题点+修正建议）

#### 2. 时间线与伏笔校验Agent
- **核心职责**：校验剧情时间逻辑与伏笔回收完整性。
- **校验维度**：时间线是否冲突、事件顺序是否正确、伏笔是否按计划埋设/回收、场景时间是否连贯
- **输出**：时间线校验报告（合规/不合规+具体问题点+修正建议）

#### 3. 格式与合规校验Agent
- **核心职责**：校验格式规范与基础合规性。
- **校验维度**：剧本格式标准度、台词是否有穿越词汇、世界观细节是否符合设定、是否有违禁内容
- **输出**：格式合规校验报告

### （五）统稿优化层 · 1个
#### 全局统稿Agent
- **核心定位**：最终质量打磨师，负责全稿风格统一与节奏优化。
- **核心职责**：
  1.  统一全剧台词风格、叙事节奏，修正不同场次的文风差异；
  2.  优化整体叙事流畅度，补全场次间的过渡衔接；
  3.  基于全局视角，调整关键情节的情绪张力与节奏快慢。
- **输入**：全剧正式剧本初稿、官方资产库
- **输出**：全剧剧本终稿
- **权限**：可修改正式剧本库内容，保留修改痕迹

## 三、全流程工作流节点清单
共5大阶段21个核心节点，严格串行推进，局部环节可并行。每个节点均含准入条件、执行逻辑、输出产物、准出标准，可直接映射为工作流引擎的节点配置。

| N02 | 原著文本拆分与分层摘要 | 原著解构Agent | N01完成，原著文件已入库 | 1. 识别原著章节与剧情单元天然边界；2. 按三级拆分规则生成弹性语义块，保证单块叙事完整性；3. 逐块生成结构化摘要与五类基础信息标签；4. 自下而上聚合生成单元级、全局级分层摘要；5. 完成全量语义块元信息标注 | 带元信息的语义块集合、分层摘要体系、原著基础标签库 | 1. 所有拆分点均位于语义边界，无对话/情节中段硬切；2. 语义块字数符合对应模型的弹性区间要求；3. 摘要覆盖全文无章节遗漏；4. 五类基础标签维度完整，核心信息无遗漏 |

## 四、核心节点专项细则
### 4.1 N02 节点：语义块拆分专项规则
本细则为节点核心执行逻辑的落地补充，原著解构Agent必须严格遵循，从根源控制拆分质量对后续全流程的传导影响。

#### 4.1.1 三级拆分优先级（从高到低，禁止跨级硬切）
拆分严格按「天然叙事边界 > 剧情语义边界 > 字数兜底约束」的顺序判断，绝不以纯字数为第一标准。
- **一级边界（最高优先级）**：原著章节、卷、篇的天然分隔线。绝不跨章节、跨剧情大单元强行合并或拆分，优先保留单章叙事完整性。
- **二级边界（次优先级）**：章节内的剧情语义转场点。仅当单章体量超标时启用，仅在场景切换、时间跳转、核心人物更换、主情节段落收尾、对话结束处拆分，禁止在动作戏、关键对话、高潮情节中段切割。
- **三级边界（兜底约束）**：字数弹性区间。仅作为合规性校验的兜底标准，根据项目选用的基础模型能力动态调整。

#### 4.1.2 字数偏离的影响与风险控制
字数区间的本质是平衡「信息完整度」与「模型处理质量」，偏离区间会直接影响后续全链路产出，对应风险与控制规则如下：
- **单块过小（低于对应模型下限）**
  核心影响：语义块数量激增，分层摘要聚合次数增多，信息误差逐层累积，易导致全局摘要丢失细节逻辑；人物、伏笔等标签碎片化；模型调用成本与耗时翻倍。
  控制规则：单章字数不足1500字时，仅可与同剧情单元的相邻章节合并，直至触低下限或该剧情单元结束；禁止跨卷、跨核心剧情单元合并。
- **单块过大（高于对应模型上限）**
  核心影响：模型输入占比过高，输出空间被挤压，摘要被迫粗化，遗漏次要人物、关键伏笔、世界观细节；触发长文本「中段遗忘」效应，块内中间部分信息提取质量显著下降。
  控制规则：单章字数超上限时，必须在章节内按二级语义边界拆分为多个子块，每个子块严格控制在弹性区间内，拆分后保留所属章节与剧情单元的关联元信息。

#### 4.1.3 分模型适配的弹性字数区间
根据项目选用的基础模型上下文窗口，动态匹配拆分字数标准；中文按1字≈1.3-1.5token换算，统一预留50%上下文空间用于输出摘要与标签。
| 模型上下文能力 | 单块字数弹性区间 | 单章免拆分阈值 | 适用场景 |
| :--- | :--- | :--- | :--- |
| 8K 通用模型 | 2000-5000字 | 5000字以内整章处理 | 中小体量项目、低成本快速落地 |
| 16K-32K 主流模型 | 3000-8000字 | 8000字以内整章处理 | 主流商用项目、平衡质量与成本 |
| 128K+ 长上下文模型 | 5000-20000字 | 20000字以内整章处理 | 高质量精品项目、最大化保留叙事完整性 |

#### 4.1.4 语义块强制元信息
每个拆分完成的语义块，必须附带以下结构化元信息，用于后续聚合、检索与校验：
- 所属卷/部、所属章节、所属剧情单元
- 核心出场人物、核心场景、核心事件类型
- 语义块序号、前后块关联标识

### 4.2 N03 节点：首轮资产库构建配置细则
#### 4.2.1 节点基础信息
- 节点编号：N03

#### 4.2.2 节点整体执行流程
1.  项目调度Agent向三个Agent同时分发任务，附带对应数据的读取权限；
2.  三个Agent并行完成各自领域的信息聚合、去重、补全、初校验，生成初稿；

4.  校验通过则发布资产库v1.0，存入工作层；校验不通过则返回对应Agent修正，直至通过。

#### 4.2.3 子节点1：人物资产库构建
- **执行角色**：人设资产管理Agent
- **输入数据**：章节级人物标签、全局摘要人物信息、原著基础出场人物清单
- **执行步骤**：
  1.  **全量聚合**：按人物姓名/别名，跨章节聚合所有相关信息，合并重复条目，统一人物唯一标识；
  2.  **字段补全**：按标准字段填充人物信息，信息不足的标注「待补充」，禁止编造；
  3.  **去重合并**：识别同一人物的不同称谓（本名、字号、外号、身份代称），合并为同一档案，标注所有别名；
  4.  **关系梳理**：梳理人物间的核心关系（亲属、敌对、盟友、师徒等），生成初步人物关系网；
  5.  **初校验**：排查同一人物的年龄、身份、性格是否存在前后明显矛盾，存在矛盾的标注「冲突待确认」，并列出冲突点原文依据。
- **输出字段规范**：
  | 字段名 | 说明 | 必填性 |
  | :--- | :--- | :--- |
  | 人物ID | 唯一标识，如CHAR-001 | 必填 |
  | 姓名/别名 | 本名、字号、外号、所有剧中称谓 | 必填 |
  | 核心身份 | 开篇身份、核心社会定位 | 必填 |
  | 外貌特征 | 标志性外貌、服饰特征 | 选填 |
  | 核心性格 | 开篇核心性格特质、行为模式 | 必填 |
  | 语言风格 | 台词特点、说话习惯 | 选填 |
  | 关键经历 | 原著中影响人物的核心过往事件 | 必填 |
  | 人物目标 | 原著中的核心诉求与终极目标 | 必填 |
  | 人物关系 | 与其他核心人物的关系及变化 | 必填 |
  | 人物弧光 | 从开篇到结局的性格/身份变化 | 选填 |
  | 标志性行为 | 贯穿全程的习惯性动作/偏好 | 选填 |
  | 冲突标记 | 原著中存在的设定矛盾点 | 有则填 |
- **准出标准**：核心人物（TOP10）字段完整度≥90%，次要人物字段完整度≥60%，明显冲突点全部标注。

#### 4.2.4 子节点2：世界观资产库构建
- **执行角色**：世界观资产管理Agent
- **输入数据**：章节级场景/设定标签、全局世界观摘要、原著时代/地理相关信息
- **执行步骤**：
  1.  **分类聚合**：按「时代背景、地理设定、势力划分、社会规则、服饰器物、礼仪称谓、核心场景」七大维度聚合信息；
  2.  **规则提炼**：提炼世界观的底层运行规则（如阶级制度、权力体系、特殊能力规则等），明确通用约束；
  3.  **场景建档**：对核心场景（出现≥3次或有关键情节）单独建档，标注空间特征、视觉氛围、出场功能；
  4.  **统一规范**：对称谓、官职、器物名称做统一，避免同一事物多种表述；
  5.  **初校验**：排查设定前后矛盾，如时间线与时代特征不符、规则前后不一致，标注冲突点。
- **输出字段规范**：
  1.  基础设定模块：时代背景、地理疆域、核心势力、社会阶层、通用规则
  2.  文化细节模块：服饰规制、饮食器物、礼仪称谓、习俗制度
  3.  核心场景库：场景ID、场景名称、空间类型、视觉特征、出现章节、核心功能
- **准出标准**：七大维度无核心缺失，核心场景全部建档，基础规则无明显逻辑冲突。

#### 4.2.5 子节点3：全局时间线构建
- **执行角色**：时间线管理Agent
- **输入数据**：章节级事件标签、全局故事摘要、关键节点时间信息
- **执行步骤**：
  1.  **事件提取**：提取所有影响主线的关键事件，标注事件发生的相对/绝对时间、涉及人物、发生地点；
  2.  **时序排序**：按时间先后排序，梳理主线时间轴，标注支线事件的时间对应关系；
  3.  **伏笔标记**：识别所有伏笔埋设事件与对应回收事件，生成初步伏笔-回收对照表；
  4.  **初校验**：排查时间悖论（如人物年龄与事件时间不符、因果倒置），标注冲突点。
- **输出字段规范**：
  1.  主线时间轴：时间节点、核心事件、涉及人物、事件影响
  2.  支线时间轴：各支线的关键事件与主线时间对应关系
  3.  伏笔回收对照表：伏笔ID、埋设位置（章节）、伏笔内容、回收位置（章节）、回收方式
- **准出标准**：主线关键事件无遗漏，时序逻辑正确，明显伏笔全部标记，无核心时间悖论。

#### 4.2.6 跨资产一致性校验（节点必经环节）
- **触发条件**：三个子节点全部完成初稿
- **执行逻辑**：由项目调度Agent触发，三个Agent交叉校验对方数据
  1.  人物经历 vs 时间线：校验人物关键经历是否与时间轴节点对应；
  2.  人物身份 vs 世界观：校验人物身份、称谓是否符合世界观的社会规则；
  3.  场景事件 vs 时间线：校验核心场景的关键事件是否与时序匹配。
- **异常处理**：发现不一致处，标注问题点，退回对应Agent修正；单轮修正上限2次，超限则标记为「待人工确认」，不阻塞流程，留待后续节点人工处理。
- **最终发布**：校验通过后，正式发布「官方资产库v1.0」，存入共享工作区工作层，供N04改编策划调用。

## 铁律一：禁止任何形式的心理描写
-   **绝对禁止**：内心独白、心理活动描述、情绪形容词堆砌（如"他感到悲伤""她内心挣扎""他想起过去"）
-   **正确做法**：将一切心理内容转化为外部动作、台词潜台词、表情变化、身体语言、环境互动
-   **违规案例**："李明站在窗前，心中五味杂陈，想起了十年前的那个雨夜。"
-   **合规改写**："李明站在窗前。手松开，烟头从十三楼坠落。他盯着烟头消失的方向，嘴角扯了一下——像笑，又不像。（对窗外）'十年了，还是这个鬼天气。'"
-   **校验标准**：剧本中出现的每一句话，摄影师都必须知道镜头对准什么，演员都必须知道身体该怎么演。

## 铁律二：台词必须"一人一声"
-   每个人的台词必须严格匹配其人物设定中的语言风格、教育背景、性格特征
-   **绝对禁止**：所有角色说同一种"AI腔"——句式工整、逻辑完整、缺乏口头禅和语癖
-   **正确做法**：
    -   武将的台词短促、有力量感，不拽文
    -   谋士的台词有逻辑层次，但不说教
    -   市井人物的台词有语病、有方言词、有口头禅
    -   上位者的台词简短、留白多、话里有话
-   **自检方法**：遮住角色名，读一遍台词——如果能分辨出是谁在说话，通过；如果所有人听起来像同一个人，打回重写。

## 铁律三：零静态情绪描写
-   **绝对禁止**：用"沉默""对视""眼神交流""气氛凝重"等静态描写填充戏剧冲突
-   **正确做法**：每个情感节拍必须有一个可拍摄的物理动作支撑
-   **每场硬指标**：至少包含2个以上的实质性戏剧动作（人物主动做了什么事来改变当前局面），而非被动反应或静态对峙。
-   **违规案例**："两人对视，沉默了很久。气氛越来越紧张。"
-   **合规改写**："张伟盯着她。他把茶杯推过去——推到桌子正中间，手指在杯沿上停了两秒才收回。'喝了。'他退后一步，抱起双臂。她不碰杯子，站起来走向门口。'你敢走出去。'她停住——手已经搭在门把上了。但还是停了。"

## 铁律四：每场戏必须有"信息增量"
-   本场结束时，观众必须知道了本场开始前不知道的事情（人物动机、剧情推进、关系变化、伏笔暗示），否则本场是废戏
-   自检：删掉本场，后面有没有哪场戏会看不懂？如果没有，本场无效，必须重写。

## 铁律五：场景即叙事
-   环境不是背景板。人物的身份、心态、处境必须通过其与场景的互动来呈现，而非旁白说明
-   **正确做法**：利用场景中的道具、空间结构、光线条件让人物"演"出来
-   **示例**：写一个人穷——不是说他穷，而是写他进面馆先看墙上价格、点完单掏钱时数了两遍零钱、吃完要把汤喝干净

## 六、商用级配套落地机制
1.  **版本管理机制**：所有资产与剧本均带版本号，修改自动生成新版本，保留历史回溯能力；官方资产库升级需走审批流程。
2.  **回滚机制**：任意节点出现问题，可一键回滚到上一稳定版本，避免错误传导。
3.  **并行调度规则**：同阶段内的独立任务（如多集拆分、多场生成）可并行，有依赖关系的节点严格串行。
4.  **人工介入节点**：在N05（策划案）、N08（大纲）、N20（终稿）设置人工审核节点，关键决策由人把控，AI负责执行与校验。
5.  **资产补充提案机制**：创作执行层Agent（N09/N11）在创作过程中，若发现官方资产库未覆盖的设定细节（如配角口头禅、场景布局细节、未记录的人物关系），可通过标准化提案接口向资产层提交补充建议。资产Agent定期批量审核提案，通过后纳入资产库并升级小版本号（如v2.0→v2.1）。提案格式为结构化JSON：`{提案来源节点, 资产类型(人物/世界观/时间线), 字段路径, 建议值, 原文依据摘录, 提案理由}`。此机制在不破坏资产层只读安全性的前提下，为创作过程中涌现的合理设定补充提供正规回流通道。
6.  **分级校验标准**：校验Agent输出不再仅分"合规/不合规"二元，而是按严重程度分为三级——**阻塞级**（人设严重偏离、时间线因果倒置，必须修复后重新校验）、**警告级**（台词风格轻微偏差、次要细节差异，记录但不阻塞流程，同一人物/场景的警告级偏差累积3次自动升级为阻塞级）、**建议级**（不影响合规但存在优化空间，仅作为统稿阶段的参考输入）。

- 跳过 N05（策划案合规校验）：Thin Slice 阶段以验证创作为主，合规校验暂用人工快速过一遍替代

- N07 只生成1集大纲（对应选中的剧情单元），而非全剧大纲

- 跳过 N13/N14（时间线/格式校验）：由人工在人设校验后一并评估

| 假设编号 | 核心假设 | 验证方式 | 通过标准 |
| :--- | :--- | :--- | :--- |
| H1 | N02 原著解构能正确识别语义边界，分层摘要不丢失核心信息 | 对比原文与摘要，人工检查5个随机语义块 | 核心人物/事件/伏笔无遗漏，拆分点100%位于语义边界 |
| H2 | N03 能聚合出去重、无明显冲突的人物/世界观/时间线资产 | 人工审查资产库v1.0 | 核心人物字段完整度≥90%，无核心设定冲突 |
| H3 | N11 单场剧本能完成小说→视听语言的有效转化 | 人工评估3场剧本样本 | 无心理独白、台词符合人设、每场有可拍摄的物理动作 |
| H4 | N12 人设校验能准确识别剧本中的人设偏差 | 人工在校验报告中掺入2个已知偏差，检查是否被检出 | 已知偏差100%检出，无误报阻塞 |

### 8.3 Thin Slice 成功/失败判断标准

| 结果 | 判断标准 | 下一步行动 |
| :--- | :--- | :--- |
| **通过** | 4项假设全部达标 | 进入完整体系搭建，按阶段一→五逐步实现 |
| **条件通过** | H1/H2 通过，H3/H4 未达标的根因可定位且可修复 | 修复 Prompt/流程后重新跑 Thin Slice，不进入全体系搭建 |
| **失败** | H1 未通过（语义边界识别失败或核心信息遗漏） | 暂停全流程，重新评估模型选型或拆分策略；N02 是全链路根基，此处失败则下游全部不可信 |

### 8.4 评估方法

人工评估使用结构化评分表，避免主观印象。每项1-5分：

**单场剧本评估维度（每场独立打分）**：
1. 视听转化度（无心理描写，所有内容可被拍摄）
2. 台词人设匹配度（每句台词符合该人物语言风格）
3. 信息增量（本场结束时有明确的新信息传递）
4. 戏剧动作密度（每场≥2个实质性物理动作）
5. 格式规范度（完全符合标准剧本格式）

**综合通过线**：3场样本平均分≥3.5，且无单项1分的场次。

## 九、模型能力风险矩阵

本体系所有 Agent 依赖同一底层模型，仅靠 Prompt 区分行为。不同 Agent 对模型能力的要求差异显著，以下标注每个 Agent 在主流模型（32K上下文）下的已知风险点和缓解措施。

### 9.1 风险等级说明

| 等级 | 含义 | 应对策略 |
| :--- | :--- | :--- |
| 🟢 低风险 | 任务在模型能力边界内，Prompt 可充分约束 | 标准 Prompt 即可，无需额外措施 |
| 🟡 中风险 | 存在已知的模型倾向性偏差，需 Prompt 中设置硬规则对抗 | Prompt 中内置负面示例 + 硬性禁止项 |
| 🔴 高风险 | 任务触及模型能力瓶颈，仅靠 Prompt 无法完全解决 | 需流程层面的冗余设计（多重校验、人工抽检、降级策略） |

### 9.2 各 Agent 风险评级

| Agent | 风险等级 | 核心风险 | 具体表现 | 缓解措施 |
| :--- | :--- | :--- | :--- | :--- |
| 原著解构Agent (N02) | 🟡 中 | 长文本中段遗忘 | 章节中间部分的关键人物、伏笔标签遗漏率显著高于首尾 | 1. 拆分语义块时首尾信息重合度≥10%（overlap策略）；2. 分层摘要自下而上聚合，底层信息不会直接被跳过；3. 建议128K+模型处理>1万字/章的作品 |
| 人设资产管理Agent (N03) | 🟢 低 | 跨章节别名合并失败 | 同一人物的多个别名（本名、字号、外号）未被合并，生成两份独立档案 | 在Prompt中内置角色别名识别策略（上下文聚类+称谓模式匹配），并设置准出标准中的"TOP10人物无重复档案"硬指标 |
| 世界观资产管理Agent (N03) | 🟢 低 | 架空设定过度脑补 | 对原著未明确描述的世界规则进行"合理推测"，但推测方向偏离改编定位 | Prompt中硬规则：信息不足标注「待补充」，禁止编造；架空题材必须显式声明锚定的历史参照 |
| 时间线管理Agent (N03) | 🟡 中 | 模糊时间表述处理 | 原著中"数日后""不久""转眼间"等模糊时间表述被忽略或随意赋值 | 要求Agent显式区分「精确时间节点」「推测时间节点」「模糊时间段」三类，模糊段标注估计区间而非确定值 |
| 改编策划Agent (N04) | 🟡 中 | 分析能力强但"过度合理化" | 为删减支线编造看似合理的理由，实际削弱了原著的情感厚度 | 要求每条删减决策附带"被删内容的情感功能"和"替代方案"；N05策划案校验侧重审查"删了什么"而非"留下了什么" |
| 分集大纲Agent (N07) | 🟡 中 | 节奏模板化 | 机械套用三幕式结构，每集都在固定位置设置冲突/钩子，导致剧集"公式感"强 | Prompt中强调"结构服务于内容"原则；N08大纲校验增加"节奏多样性"检查项 |
| 场次拆分Agent (N09) | 🟢 低 | 场次功能标签泛化 | 大量场次被标注为"推进剧情"，实际上"推进剧情"成了兜底标签，失去分类意义 | 限定叙事功能必须从6类中选1（推进剧情/塑造人物/铺垫伏笔/制造冲突/过渡衔接/情绪释放），禁止自创标签；"推进剧情"占比不得超过40% |
| 单场剧本Agent (N11) | 🔴 高 | **AI剧本味** | 1. 台词句式工整、逻辑完整、缺乏角色辨识度；2. 心理描写→静态情绪描述（"沉默""对视""气氛凝重"）；3. 动作描写泛化（"他走过去""她坐下来"），缺乏具体的物理动作设计；4. 过度使用"突然""竟然"等叙事衔接词 | **多层对抗**：1. Prompt内置大量负面案例（如铁律三的"违规/合规"对照）；2. N12人设校验专项检查台词人设匹配度；3. N14格式校验扫描禁用叙事词汇；4. Thin Slice阶段优先验证此节点；5. 建议此Agent使用最高能力模型 |
| 人设一致性校验Agent (N12) | 🟡 中 | 过度宽容 | 对轻微人设偏差（如台词风格略微偏离）放行，累积到后期形成明显漂移 | 校验标准中区分"阻塞级偏差"和"警告级偏差"，警告级偏差累积3次自动升级为阻塞级 |
| 时间线与伏笔校验Agent (N13) | 🟡 中 | 模糊时间段的漏检 | 对"数日后"等模糊表述不敏感，不检查这类时间段内的逻辑可行性（如"三日后"完成了一个月的工程量） | 校验规则中增加"模糊时间段逻辑可行性检查"：若时间段为模糊表述，检查该时间段内完成的事件量是否物理上可能 |
| 格式与合规校验Agent (N14) | 🟢 低 | 穿越词汇库不完整 | 对特定时代的禁用词汇覆盖不全（如古装剧中的现代管理学词汇） | 在N06资产库迭代时，由世界观Agent输出「禁用词汇清单」作为N14的校验基准，而非依赖模型的常识 |
| 全局统稿Agent (N17/N19) | 🔴 高 | **上下文窗口不足以容纳全剧** | 40集剧本全文远超任何模型的上下文窗口，无法一次性完成全局风格统一和跨集一致性诊断 | **分批+聚合策略**：1. N17先以单集为单位做风格优化（上下文需求小）；2. N18全局审计采用分段扫描+交叉对比（每次载入3集，滑动窗口逐段检查）；3. N19统稿采用"先提取风格指纹→逐集对齐"策略，避免一次性载入全文；4. 关键决策（如全局节奏调整）必须由人工确认 |
| 项目调度Agent (N01等) | 🟢 低 | 任务分发中的信息遗漏 | 向执行Agent分发任务时，未附带足够的上下文（如只发了场次指令没发对应原文） | 调度Agent本身不对内容做判断——它只做格式化的任务指令分发，核心风险通过"执行Agent执行前强制拉取最新数据"的架构设计来规避 |

### 9.3 风险叠加场景

以下场景会导致多个 Agent 的风险叠加放大，需特别关注：

| 叠加场景 | 涉及Agent | 叠加效应 | 特别缓解措施 |
| :--- | :--- | :--- | :--- |
| 长篇章回体小说（>100章） | N02 → N03 → N07 | N02标签遗漏 → N03资产聚合缺失 → N07大纲基于不完整信息做结构设计，错误逐级放大 | 长篇章回体强制启用128K+模型处理N02；N02完成后增加人工抽检关卡（随机5章解构质量评审） |
