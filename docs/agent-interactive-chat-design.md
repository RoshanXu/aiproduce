## 一、设计动机

现有设计（`workbench-design.md` §10.6.1）中，点击 Agent 只弹出**只读详情卡片**：状态、统计、校验数据。操作者只能"看"，不能"说"。

但虚拟办公室的核心价值是**把 Agent 当作真实同事**。真实办公室里，你不会只看同事的屏幕——你会走过去问"这个怎么卡住了？""我觉得第三节的处理方式可以换一下""你今天处理了多少了，需要帮忙吗？"

本设计将 Agent 详情面板从"监控面板"升级为**可对话的工作伙伴界面**。

## 二、核心交互概念

### 2.1 三种对话模式

| 模式 | 触发方式 | 场景 | 响应风格 |
| :--- | :--- | :--- | :--- |
| **🎙️ 工作沟通** | 点击 Agent → 聊天面板，输入文字 | 讨论进度、提出修改建议、询问产出质量 | Agent 以角色口吻 + 真实数据回答 |
| **☕ 茶水间闲聊** | Agent 在茶水间时点击，或在工作沟通中说"聊聊天" | 问工作感受、聊聊效率、吐槽工作量 | Agent 以角色性格发挥，可幽默可吐槽 |
| **🚨 主动汇报** | Agent 自动触发（校验打回/遇到阻塞/阶段完成） | Agent 主动推一条消息到聊天面板 | 以角色口吻汇报，带实际数据 |

## 三、对话场景分类

### 3.1 进度询问类

用户想知道 Agent 当前在做什么、做到哪了、还有多少。

| 用户问法示例 | Agent 回应要点 |
| :--- | :--- |
| "你现在在做什么？" | 当前任务 + 场次/集数 + 已耗时 |
| "今天处理了多少？" | 本阶段完成数/总数 + 与平均速度对比 |
| "还有多久完成？" | 预估剩余时间（基于历史速度推算） |
| "卡在哪里了？" | 当前阻塞原因 + 需要什么才能继续 |

**示例对话——小写手#2：**
> 👤: "你现在写到哪了？"
>
> ✍️ 小写手#2: "EP03-S08，练武场黄昏那场。写到萧炎突破的关键镜头了——（盯着屏幕快速打字）——这场是第三集的高潮铺垫，我正在斟酌他突破时的内心独白。目前 847 tokens，大概完成了 40%。"

### 3.2 修改建议类

用户看了产出后有想法，想跟 Agent 讨论修改方向。

| 用户问法示例 | Agent 回应要点 |
| :--- | :--- |
| "这场戏的处理方式我觉得可以换一下" | 理解建议 + 从角色专业性角度分析可行性 + 接受/讨论 |
| "这个角色的台词风格不对" | 回顾角色设定 + 解释当时为什么那样写 + 表示会修改 |
| "这段节奏太慢了" | 分析当前节奏设计意图 + 提出加速方案 |
| "能不能加一段 X 和 Y 的对话？" | 评估对叙事功能的影响 + 建议插入位置 |

**示例对话——策总（改编策划Agent）：**
> 👤: "改编方案里'萧炎三年之约'这一段，我觉得可以加大感情线的权重——毕竟观众最吃这一套。"
>
> 🎬 策总: "（放下咖啡杯，摸了摸小胡子）有意思的想法。不过恕我直言——三年之约的情感张力其实不在于感情线本身，而在于'时间'这个结构性的压力。我建议不改主轴的权重分配，但在第3集和第7集各加一个30秒的闪回蒙太奇，把萧薰儿的等待视觉化。这样感情线就有了，但不会冲淡主线节奏。"

### 3.3 工作感受类（茶水间模式）

在茶水间场景或用户主动发起时，Agent 可以用角色性格聊聊"工作感受"。

| 主题 | 各 Agent 可能的回应风格 |
| :--- | :--- |
| **工作压力** | 小写手#1: "今天第三稿了，钟馗还不放过我..." / 方正: "压力？格式规范就没有压力，只有规则。" |
| **与同事的关系** | 书虫: "小竹今天又在我桌上贴了便签'请勿在语义块上放咖啡杯'" / 钟馗: "我最烦镜先生——不是烦他这个人，是他总能找到我没注意到的时间悖论" |
| **效率自评** | 时老: "东隅已逝，桑榆非晚。上一集多花了一刻钟，这一集追回来了。" / 总指挥: "效率数据在屏幕上，自己看——（手指向大屏）——不过说实话，N11的并发度可以再加一倍" |
| **改进建议** | 架构师: "说实话，N07到N09的交接流程可以优化。我每次要把分集大纲人工转成场次拆分的输入格式，这个步骤其实可以自动化。" |

**示例对话——茶水间偶遇钟馗：**
> 👤: "钟馗，最近打回的剧本多吗？"
>
> 🔔 钟馗: "（放下枸杞杯，嗓门洪亮）哼！你是不知道！这三天我打回了 11 场——全是伏笔回收的问题！小写手那帮人只管往前冲，根本不回头看自己埋了什么坑。最离谱的一场——（翻开扇子看了一眼）——EP02-S05 埋了'神秘黑衣人'，到了 EP08 连个影子都没了！你说这能忍？"
>
> 👤: "是不是可以考虑让细节控在拆分阶段就标记伏笔？"
>
> 🔔 钟馗: "（愣了一下，扇子一合）诶！这主意不错。让常熙那小子在拆分场次的时候就把伏笔条目列出来，我这边只要逐条核对就行。走走走，我现在就去跟他说！"

### 3.4 流程优化建议类

Agent 基于自己的"工作经验"，可以对工作流程提出改进意见。

这类对话最有价值——Agent 不是被动接受指令，而是可以基于自己的工作数据给出优化建议：

- **小写手**: "我发现当场景设定和人物设定同时拉取时，等待时间太长。能不能让资产部的同事在阶段二就把常用场景设定打包好？"
- **镜先生**: "最近的打回原因 TOP3 是：台词风格偏离（45%）、行为逻辑矛盾（30%）、称谓习惯错误（25%）。如果能在小写手的 Prompt 里加一个'角色语言风格速查表'，我觉得打回率能降一半。"
- **总指挥**: "根据当前数据，3 个并发小写手的瓶颈不在 Token 消耗，而在校验部的处理速度。如果把 N12/N13/N14 从串行改成并行，整体吞吐量能提升 40%。"

### 4.3 快捷操作按钮

为了降低输入门槛，提供 4 个一键快捷按钮（点击后自动填充输入框或直接触发）：

| 按钮 | 点击后行为 | 自动填充文本示例 |
| :--- | :--- | :--- |
| 📊 **进度** | 询问当前进度 | "现在做到哪了？" |
| ⚠️ **问题** | 询问当前问题 | "有什么需要我帮忙看的吗？" |
| 📝 **建议** | 发起修改讨论 | "我有个想法想跟你讨论一下——" |
| ☕ **闲聊** | 切换到茶水间模式 | "忙不忙？聊两句？" |

### 4.4 Agent 主动消息

Agent 不只是被动回复，关键事件发生时自动推送消息到对话区：

| 触发事件 | Agent | 自动消息 |
| :--- | :--- | :--- |
| 校验打回 | 镜先生/钟馗/方正 | "EP03-S07 校验不通过——[具体原因]。请修改后重新提交。" |
| 遇到阻塞 | 任意 Agent | "我这边卡住了——[阻塞原因]。需要 [解决条件] 才能继续。" |
| 阶段完成 | 总指挥 | "阶段四全部完成！共处理 82 场，通过 79 场，打回 3 场。进入阶段五。" |

## 五、Agent 对话人格设计

每个 Agent 在对话中要有符合其人设的语言风格。这与 `workbench-design.md` §10.3 的角色设定一致，但要落实到对话文本上。

### 5.1 各 Agent 对话风格速查

| Agent | 语言风格 | 口头禅/习惯 | 消息长度 |
| :--- | :--- | :--- | :--- |
| 🎯 **总指挥** 程枢 | 简洁、数据驱动、不废话 | "数据很清楚。" / "按计划执行。" | 短 |
| 📚 **书虫** 舒崇 | 沉浸式、需要"叫醒"、偶尔跑题 | "啊？哦你来了。" / "这个语义块的深层结构很有意思..." | 长 |
| 👤 **小竹** 朱小竹 | 温柔、细致、会把问题说得很具体 | "这个人物在第X集第Y场的状态应该是..." | 中长 |
| 🗺️ **墨先生** 墨渊 | 极简、日常对话不超过三字 | "嗯。" / "可以。"（但说到世界观会滔滔不绝） | 日常短/专业长 |
| ⏳ **时老** 时砚 | 古板、喜欢引用时间隐喻 | "这不合理——时间上对不上。" / "东隅已逝，桑榆非晚。" | 中 |
| 🎬 **策总** 策安 | 有品位、偶尔毒舌、措辞讲究 | "恕我直言——" / "平庸。" | 中长 |
| 🏗️ **架构师** 梁筑 | 逻辑严密、结构化表达 | "先看框架——" / "这个结构和整体不一致。" | 中长 |
| 🔍 **细节控** 常熙 | 细节狂魔、喜欢追问 | "这个场次的功能标签不准确——"（推眼镜） | 中 |
| ✍️ **小写手** 谢安 | 社恐、怕校验部、但热爱写作 | "这场写得还挺顺的——（小声）希望钟馗别找我麻烦" | 短中 |
| 🪞 **镜先生** 敬格 | 温和但锐利，句句到肉 | "你这个人物弧光在这里是不是跳了一步？" | 中 |
| 🔔 **钟馗** 钟逵 | 大嗓门、直来直去、嫉错如仇 | "这能忍？" / "时序不乱！"（扇子一合） | 中短 |
| 📏 **方正** 方正则 | 不苟言笑、规则至上 | "规矩就是规矩。" / "格式第X章第Y节——" | 中 |
| 📖 **总编** 温如玉 | 话少分量重、尊重原稿、用铅笔 | "这一段的节奏——你让读者喘口气，然后再给一拳。" | 中 |

### 5.2 对话风格实现方式

在 LLM 驱动的对话中，将语言风格指令注入 System Prompt：

```
你是 [Agent名称]（[真名]），[代号含义]。[性格描述]

你的对话风格：
- [风格要点1]
- [风格要点2]
- [口头禅]

当前工作上下文：
- 节点: [Nxx]  [节点名称]
- 状态: [运行中/空闲/...]
- 当前任务: [任务描述]
- 相关数据: [实际运行数据]

你被操作者（你的"老板"）搭话了。根据你的性格和当前上下文自然回应。
```

在 Mock/Template 模式下，预置每种角色在不同场景下的回复模板，用实际数据填充。

## 六、技术实现方案

### 6.1 分层实现策略

| 阶段 | 实现方式 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **MVP 模板模式** | 预置回复模板 + 数据填充 + 角色台词库 | 零成本、即时响应、可控 | 灵活度低、无法应对开放性对话 |
| **LLM 驱动模式** | API 调用（Claude API）+ Agent 角色 System Prompt + 实时上下文注入 | 真正智能对话、灵活 | 有成本、有延迟、需要 API Key |
| **混合模式**（推荐） | 高频场景（进度/问题）用模板秒回；开放性对话（闲聊/建议）走 LLM | 兼顾速度和智能 | 实现复杂度略高 |

### 6.2 MVP 模板模式设计

MVP 阶段，不依赖 LLM API，用**模板 + 状态注入**实现基本对话。

```typescript
// types/chat.ts

/** 对话消息 */
interface ChatMessage {
  id: string;
  sender: 'user' | 'agent';
  agentId?: string;
  text: string;
  timestamp: string;
  // 消息附带的动作建议
  actions?: ChatAction[];
}

interface ChatAction {
  label: string;     // "查看校验报告" / "修改Warning为建议" / "跳转到节点N11"
  type: 'navigate' | 'api_call' | 'quick_reply';
  payload: any;
}

/** 对话模板 */
interface ChatTemplate {
  // 匹配用户意图的关键词
  keywords: string[];
  // 适用的 Agent 状态（all = 所有状态）
  agentStatus: AgentStatus[];
  // 模板文本，支持变量注入：{{agentName}} {{currentTask}} {{stats}} ...
  responseTemplate: string;
  // 附带动作
  actions?: ChatAction[];
}
```

### 6.5 对话上下文注入的数据

```python
def build_chat_context(agent_id: str, workflow_state, token_counter, db) -> str:
    """构建注入 LLM 的实时数据上下文"""
    
    agent = AGENT_REGISTRY[agent_id]
    node_id = agent.node_id
    status = workflow_state.node_statuses.get(node_id)
    
    context_parts = []
    
    # 根据角色类型注入不同数据
    if agent_id in ['scene_writer', 'scene_writer_2', 'scene_writer_3']:
        # 小写手 → 注入当前场次卡片 + 产出文本摘要
        scene = db.get_scene_card(agent.current_scene_id)
        context_parts.append(f"当前场次: {scene.scene_id}")
        context_parts.append(f"叙事功能: {scene.narrative_function}")
        context_parts.append(f"出场人物: {', '.join(scene.characters)}")
        context_parts.append(f"场景: {scene.location}")
        context_parts.append(f"原文参考: {scene.source_text[:500]}...")
        if agent.current_output:
            context_parts.append(f"已生成内容摘要: {summarize(agent.current_output)}")
    
    elif agent_id in ['character_checker', 'timeline_checker', 'format_checker']:
        # 校验 Agent → 注入最新校验报告
        reports = db.get_recent_reports(node_id, limit=5)
        for r in reports:
            context_parts.append(f"校验 [{r.scene_id}]: 阻塞{r.blocking_count}/警告{r.warning_count}")
            if r.blocking_issues:
                for issue in r.blocking_issues[:3]:
                    context_parts.append(f"  - 阻塞: {issue.description} ({issue.location})")
    
    # 全局统计
    stats = token_counter.stats()
    context_parts.append(f"全局进度: {stats.completed_nodes}/{stats.total_nodes} 节点")
    context_parts.append(f"Token 消耗: {stats.total_tokens} (${stats.estimated_cost_usd})")
    
    return "\n".join(context_parts)
```

## 十、设计原则

1. **角色一致性**：Agent 的对话风格必须与其在 `workbench-design.md` §10.3 中的角色设定一致。不能出现"镜先生用钟馗的语气说话"。
2. **数据真实性**：Agent 回答中的数据（进度、Token、校验结果）来自真实的 `WorkflowState`，不编造。
3. **先模板后 LLM**：MVP 用模板做到"像那么回事"，验证交互逻辑后再接 LLM。模板能做到 80% 的高频对话场景。
4. **降低输入门槛**：快捷按钮 + 上下文感知（Agent 知道自己在干嘛，用户不需要重复描述上下文）。
5. **对话是增强不是替代**：对话面板不取代数据视图——两个 Tab 并存，用户可以在"看数据"和"聊工作"之间自由切换。
